## Sampling rate

For counting steps with the accelerometer I used SENSOR_DELAY_GAME at 50 Hz. This took a sample every 20ms so each step had ~25 samples each. SENSOR_DELAY_NORMAL only have around 2-3 samples per step and SENSOR_DELAY_FASTEST costed more battery which is why I settled on GAME. If the user denies access the system falls back onto SENSOR_DELAY_UI. 

## Ethics reflection

The app only stores the date and amount of steps total, it doesn't track specific timestamps for steps nor location data. Days older than 90 days are deleted automatically and theres an option to delete all history. Data lives only on the phone but there's an option to enable cloud backup. Users have to give consent for tracking. Despite this given weeks of daily totals attributes like a person's daily routine or things like job loss or pregnancy could reveal themselves and this info could potentially be sold to advertisers. This could maybe be counteracted by having shorter or user chosen retention periods for data and a notice to users  on the app.
